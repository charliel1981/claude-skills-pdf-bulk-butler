# Multi-Language, Multi-Locale, Multi-Currency — PDF Butler

How one DocConfig services many languages, currencies, brands, and regions.

## Mental model

Three orthogonal axes produce localised output:

| Axis | Mechanism |
|---|---|
| **Template variation** (e.g. EN vs DE wording, or brand A vs brand B) | **Alternatives** on the DocConfig |
| **Locale-driven formatting** (dates, numbers, phone, currency) | `locale` / `country` / `numCurrLocale` / `timeZone` on `ConvertDataModel` |
| **In-document text translation** (labels, picklist values) | Custom Labels DataSource + Picklist Translations DataSource |

Most production setups use all three.

---

## Alternatives — template variants

**Purpose**: attach multiple templates to ONE DocConfig — runtime picks which one. Used for language variants, regional versions, brand variants.
**Select at runtime**: `cdm.alternativeName = 'DE'` (or `FR`, `ACME_BRAND`, etc.).
**Typical naming**: language code (`EN`, `DE`, `FR`, `NL`), region (`EU`, `US`), or brand tag.
**Benefit over duplicate DocConfigs**: DataSources / Configs are shared; only the template file + labels differ.

## Locale-driven formatting

### Fields on `ConvertController.ConvertDataModel`

| Field | Controls |
|---|---|
| `locale` | Overall locale string (e.g. `nl_BE`, `de_DE`, `en_US`, `fr_FR`) — auto-extracts language |
| `language` | Override just the language portion |
| `country` | DateTime formatting country |
| `numCurrLocale` | Number + currency format (may differ from document language) |
| `timeZone` | DateTime tz |

**Known locale strings**: `nl_BE`, `fr_BE`, `de_BE`, `en_US`, `en_UK`, `de_DE`, `nl_NL` + any standard `xx_YY` combo.

### What gets locale-formatted automatically

- **Dates** — month/day names translated, date format shifts (`14/03/2026` in nl_BE, `03/14/2026` in en_US)
- **Numbers** — decimal/thousand separators per locale
- **Currencies** — ISO symbol + format
- **Phone numbers** — per phone-format option below

### User locale vs customer locale

Two patterns:
- **User locale** — read from `UserInfo.getLocale()`, default behaviour
- **Customer locale** — supplied per-record (e.g. Account's Billing Country) via `cdm.locale` override

Override at generation: `cdm.locale = accountRec.BillingCountry == 'DE' ? 'de_DE' : 'en_US';`

## Phone number formatting

SINGLE ConfigType's **`PHONE`** field type supports two modes. Academy verbatim:

| Mode | Behaviour |
|---|---|
| `INTERNATIONAL` | "will add the country-code to the number" (e.g. `+32` for Belgium, `+1` for US) |
| `NATIONAL` | "formats the number for use in the country itself" (no country code) |

Resolution depends on `country` / `locale` on `ConvertDataModel`. Use `INTERNATIONAL` when the document crosses borders.

_Source: [PHONE Number Formatting](https://www.pdfbutler.com/academy/pdf-butler-academy/multi-language-multi-locale-multi-currency-multi-template-or-multi-branding/phone-number-formatting/)._

## Custom Labels

**Purpose**: translate static strings (button labels, headings, legal boilerplate) in a document.
**Salesforce source**: Custom Labels under Setup → Custom Labels.
**Two retrieval methods**:
1. **Static Values DataSource** — simpler, no Apex
2. **Actionable** (Apex `BEFORE`) — advanced, for bulk label loading with locale resolution

**Benefit**: one translation spot for all documents, managed by admins alongside the org's UI strings.

---

## Picklist Translations DataSource

**Purpose**: resolve translated picklist labels from **Translation Workbench** instead of storing API names / English labels.
**Setup**:
1. Translation Workbench → add the picklist field for each language you want
2. Create a `PICKLIST_TRANSLATIONS` DataSource in the DocConfig
3. On the `SINGLE` ConfigType rendering the picklist, tick **Translate** and point at the translation DataSource
**At runtime**: uses `locale` on `ConvertDataModel` to pick correct translation.

## Multi-currency orgs

**Org state**: Salesforce multi-currency enabled → records carry `CurrencyIsoCode`.

**Common needs**:
- Display the record's currency symbol inside the doc
- Format amounts by **customer's locale**, not the running user's

**Handled via**:
- SOQL DataSource includes `CurrencyIsoCode` + amount fields
- `cdm.numCurrLocale` set per-record (e.g. `de_DE` for a German customer) for amount formatting
- `$CurrencyIsoCode` or merge field for the symbol itself

Org-level default currency is user-locale-dependent unless you explicitly override per generation.

## Salesforce CPQ product translations

**Free add-on**: request from `support@pdfbutler.com`.
**Purpose**: leverage CPQ's own Localisation / Product Translation config inside PDF Butler documents.
**Covers**: Text, Text-Area, and Rich Text product fields.
**Benefit**: one source of truth (CPQ Localisation) for both the CPQ UI and the generated quote document.

The exact SBQQ object name is not spelled out on the Academy page — query the installed org (e.g. `sf sobject list -o <alias> | grep -i SBQQ_.*ocal`) to confirm which `SBQQ__*` object your CPQ package version exposes.

_Source: [Salesforce CPQ Product Translations/Localizations](https://www.pdfbutler.com/academy/pdf-butler-academy/multi-language-multi-locale-multi-currency-multi-template-or-multi-branding/salesforce-cpq-product-translations-localizations/)._

## Recipe: one Opportunity → three language variants

1. Create DocConfig with Alternatives: `EN`, `DE`, `FR`
2. Upload 3 templates, one per Alternative (use same merge field names)
3. Configure Custom Labels DataSource referencing translated labels
4. Configure Picklist Translations DataSource for locale-aware picklists

**Apex**:

```apex
for (String lang : new List<String>{'EN', 'DE', 'FR'}) {
    cadmus_core.ConvertController.ConvertDataModel cdm =
        new cadmus_core.ConvertController.ConvertDataModel();
    cdm.objectId         = opportunityId;
    cdm.docConfigId      = docConfigId;
    cdm.alternativeName  = lang;
    cdm.locale           = lang == 'DE' ? 'de_DE' : lang == 'FR' ? 'fr_FR' : 'en_US';
    cdm.numCurrLocale    = cdm.locale;
    cadmus_core.DocGenerationWrapper wrap =
        cadmus_core.ConvertController.convertWithWrapper(cdm);
    // save wrap.response.base64 per language...
}
```

## Failure modes

| Symptom | Root cause | Fix |
|---|---|---|
| Numbers rendered with wrong decimal separator | `numCurrLocale` unset (falls back to running user's locale) | Set `cdm.numCurrLocale` per record |
| Dates render in English month names but wrong date order | `language` set but `country` unset | Set `country` — DateTime formatting needs both |
| Multi-currency org: symbols wrong | SOQL missing `CurrencyIsoCode` | Add `CurrencyIsoCode` to every currency-bearing DataSource |
| Picklist values in wrong language | `PICKLIST_TRANSLATIONS` DS absent or unlinked on the SINGLE ConfigType | Create the DS, tick "Translate" on the SINGLE, point at the DS |
| Phone number shows `+32` in a national doc | `PHONE` mode set to `INTERNATIONAL` | Switch to `NATIONAL` |
| Alternative not applied | `cdm.alternativeName` mismatch with DocConfig Alternative name (case-sensitive) | Echo Alternative names via `Sync Alternative Names` on the DocConfig to cross-check |
