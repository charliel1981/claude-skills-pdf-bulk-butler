# DataSources — PDF Butler

Every DataSource type. Claude reads this when wiring data into a DocConfig.

## Quick chooser

| User need | DataSource |
|---|---|
| The triggering record itself | `SINGLE` |
| Related list (child records) | `LIST` |
| Build SOQL via UI, no code | SOQL Builder |
| Write raw SOQL with aggregates / grouping | Full SOQL Power |
| Static literals (company address, etc.) | `STATIC VALUES` |
| Data from a Salesforce Report | `REPORT` |
| Images from Files/Attachments/URLs | `PICTURE` |
| Hundreds of images, bypass SFDC limits | Late Binding Dynamic Pictures |
| Key-value data populated by Apex | `KEYVALUE` |
| Rollup without a real rollup-summary field | Rollup summaries DataSource |
| Same-query re-used with different filters | Filtered DataSources |
| Multi-level parent→child data model | Nested DataSources |
| Translated picklist labels per locale | Picklist Translations |

## Catalog

### `SINGLE`

**Purpose**: exactly 1 record. Usually the triggering record (Quote, Opportunity, Case).
**SOQL**: `SELECT ... FROM Object WHERE Id = :objectId` (bind variable `:objectId` injected by PDF Butler).
**Use when**: pulling header-level data for a document.

### `LIST`

**Purpose**: multiple records — usually children of the triggering record.
**Examples**: Opportunity Products, Quote Lines, Assets.
**SOQL**: typical parent-filtered query, e.g. `SELECT ... FROM OpportunityLineItem WHERE OpportunityId = :objectId`.
**Consumed by**: `TABLE`, `TABLE_ROW`, `PARAGRAPH`, any repeating ConfigType.

### SOQL Builder

**Purpose**: declarative query construction for admins — pick object, fields, filters via UI.
**Output**: generates the SOQL the same runtime would accept from Full SOQL Power. Good for users who don't write Apex/SOQL by hand.

### Full SOQL Power

**Purpose**: write your own SOQL, unlocks everything SOQL supports.
**Features**:
- Aggregate functions (`AVG`, `SUM`, `MIN`, `MAX`)
- `GROUP BY` clauses
- `LIMIT`
- Complex `WHERE`
**Bind variables**: `:objectId` (triggering record), plus user-seeded `inputMap` values.
**Use when**: SOQL Builder can't express what you need (aggregates, complex joins).

### `STATIC VALUES`

**Purpose**: literal, reusable values (company address, support phone, legal boilerplate).
**Benefit**: update once, ripples across every DocConfig that references it.
**Also used for**: `PICTURE_TO_URL` image URLs, long email recipient lists (`;`-separated).

### `PICTURE`

**Purpose**: pull images from Salesforce Documents, Files, or Attachments.
**Consumed by**: `PICTURE` ConfigType, `INLINE_REPEATER` for PICTURE.
**Related**: `PICTURE_TO_URL` ConfigType (URL-referenced images for email), Late Binding for bulk.

### `KEYVALUE`

**Purpose**: accept data generated by Apex (`AbstractBeforeActionable`) rather than SOQL.
**Population pattern**: Apex puts `Map<String, Object>` or `List<Map<String, Object>>` into the `inputMap` keyed by the DataSource Id.
**Use for**: data from external APIs, computed values, transformed JSON, or any shape SOQL can't produce.
**Canonical example**: `APEXActionablesKEYVALUES.pdf` on the Academy shows JSON → KEYVALUE transformations.

**Typed wrapper classes** (use instead of raw `Map<String, Object>` when intent matters):

```apex
// Single-record shape — pair with SINGLE-shaped KEYVALUE
global with sharing class cadmus_core.SingleWrapper {
    global SingleWrapper();
    global Map<String, Object> data;   // KEYVALUE payload
    global Object sfdcData;            // raw sObject for the row
    global String type;
}

// List shape — pair with LIST-shaped KEYVALUE
global with sharing class cadmus_core.ListWrapper {
    global ListWrapper();
    global List<Map<String, Object>> data;   // KEYVALUE rows
    global List<Object> sfdcData;            // raw sObject rows
    global String type;
}
```

Seed either into the Before Actionable's `inputMap`, keyed by the customer DataSource Id.

_Sources: [`SingleWrapper.html`](https://eu1.pdfbutler.com/files/api/cadmuscore/SingleWrapper.html), [`ListWrapper.html`](https://eu1.pdfbutler.com/files/api/cadmuscore/ListWrapper.html)._

### `REPORT`

**Purpose**: use a Salesforce Report as the data source.
**Format constraint**: **tabular reports only**.
**Label vs value**: reports auto-format currency, user lookups, etc. You can switch to raw values if you want to apply PDF Butler's own formatting or feed into `SINGLE_FOR_FORMULA`.
**Performance warning**: Salesforce report execution is **slow** — prefer SOQL DataSource when possible.

### Filtered DataSources

**Purpose**: derive a narrower DataSource from an existing one without re-querying.
**Benefit**: query Salesforce once, slice the result multiple ways — reduces governor impact.
**Two flavours**: Filtered DataSource, Filtered Child DataSource (for nested hierarchies).

### Late Binding Dynamic Pictures

**Problem solved**: SFDC image-count / heap limits when embedding many images.
**Mechanism**: PDF Butler fetches images **directly during render** — not through Salesforce callouts.
**Performance**: parallel image fetching, up to **~300 images per generation**.
**Use for**: product catalogues, personalised marketing docs with many images.

### Rollup summaries DataSource

**Purpose**: work around Salesforce rollup-summary limits (master-detail only; 25-per-object cap) by computing aggregates at doc-generation time.
**Covers**: SUM, COUNT, AVG-style aggregates across related records.
**Use when**: you need a rollup but can't add one, or have exhausted the per-object quota.

### Nested (Parent-Child) DataSources

**Purpose**: model hierarchical data for complex document layouts.
**Canonical patterns**:
| Parent | Child | Output |
|---|---|---|
| `TABLE` | `TABLE_ROW` | Standard repeating table |
| `TABLE_ROW` | `PARAGRAPH` | Row containing repeating paragraphs |
| `TABLE` | Paragraph-in-Cell | Cell containing repeating text |
| `TABLE` | 2× rows | Multi-row-per-iteration pattern |
**Note**: the Academy calls this "one of the most powerful but hardest to understand" features.
**Linking**: parent-child linked by query parent-ID matching / explicit linking fields (check Academy for current exact field names).

### Picklist Translations

**Purpose**: resolve translated picklist labels from Salesforce **Translation Workbench** based on user/document locale.
**Benefit**: stop hardcoding translated values in documents — central maintenance in Setup → Translation Workbench.
**Consumed by**: `SINGLE` ConfigType with "Translate" option pointing at this DS.

## Cross-reference

- SOQL bind variables, locale, and `inputMap` seeding happen on `ConvertController.ConvertDataModel` — see `reference/automation.md`.
- `:` and `|` characters are **reserved** in Flow-sourced inputs to DataSources — wrap with `URLENCODE()` in Flow formulas.
- Large-volume image workflows: **Late Binding** (no Apex needed) > `Image by URL` Actionable > embedded `PICTURE` DS.
